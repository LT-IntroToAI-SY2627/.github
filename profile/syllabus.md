## Course Overview

Introduction to AI is a full-year course that teaches Python programming alongside the concepts and tools driving modern artificial intelligence. Students begin by learning core programming skills, then apply those skills to building a real, class-wide software project that grows unit by unit throughout the semester. In the second semester, students dive into machine learning, data analysis, and neural networks.

This course is positioned between Programming 1 and Programming 2. Students are expected to have basic programming experience coming in. By the end of the year, students will have contributed to a shared codebase, used professional developer tools, and built a working AI-powered application.

Generative AI tools are a core part of this course — not something to avoid. Students will learn how to use AI effectively as a coding assistant, how to evaluate AI-generated output critically, and when and why to write code themselves. Quizzes test understanding without AI access, so students are expected to genuinely understand the material, not just be able to prompt for it.

| Unit | Activities | Description | Key Concepts |

| **Unit 1 — Python Basics & GitHub** (~4 weeks) | GitHub assignments, Python exercise, project contribution, quiz | Core Python syntax and GitHub workflow. Class votes on and begins the shared project. | Variables, functions, loops, conditionals, branching, pull requests |

## Grading

| Category | Weight | Description |
|---|---|---|
| **In-Class Activities** | 20% | Short tasks completed during class — warm-ups, unplugged activities, live coding exercises, and participation. Graded on effort and completion. |
| **Formative Assignments** | 50% | GitHub assignments, standalone coding exercises, and project contributions submitted throughout each unit. AI is permitted and encouraged. Graded on correctness, code quality, and GitHub workflow. |
| **Summative Quiz** | 30% | One quiz per unit taken without AI assistance. Tests genuine understanding of Python concepts and AI literacy. Quizzes include code reading, short answer, and debugging questions. |

> **A note on partial credit and resubmission:** Assignments use baseline scoring — submitting something always earns partial credit. Students are encouraged to resubmit revised work to demonstrate improvement. A single mistake should not wipe out an entire score.

## AI Use & Academic Integrity

This course takes a different approach to AI than most. Rather than restricting AI tools, we treat them as professional instruments that developers use every day — and we learn to use them responsibly.

### When AI is allowed
- All formative assignments and in-class exercises
- Exploring, experimenting, and learning — using AI to understand a concept is encouraged
- Generating code to study, critique, or improve

### When AI is not allowed
- Unit quizzes — no AI tools of any kind during assessments
- Any activity explicitly marked as no-AI by the instructor

### Expectations when using AI
- Students must be able to explain any AI-generated code in their own words
- Using AI to complete work you do not understand is self-defeating — quizzes will reflect what you actually know
- If AI is used significantly on an assignment, note it in a comment or commit message

> This course abides by all Lane Tech College Prep academic integrity policies. Students are expected to be familiar with and follow the guidelines outlined in the student handbook. Violations will be handled in accordance with school policy.

## Classroom Expectations

### For students
- Come ready to work — log into your VM and pull up the day's materials at the start of class
- Ask questions early — a GitHub error or a broken function is much easier to fix when caught right away
- Respect classmates' code — never edit another student's file in the shared repository
- Contribute honestly — your project contributions will be visible in the commit history
- Be a good collaborator — peer reviews should be thoughtful and constructive

### For the instructor
- Provide clear expectations for every assignment before it is due
- Return feedback on pull requests within a reasonable window
- Allow resubmission opportunities when students demonstrate genuine effort to improve
- Adjust pacing when the class needs more time — the goal is understanding, not speed
